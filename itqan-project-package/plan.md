# خطة تنفيذ إتقان جلوبال — مطابقة وثيقة المواصفات

## القرار التنفيذي

المطلوب هو تحويل إتقان جلوبال من واجهة عرض ونواة Full-Stack إلى منصة EdTech & Gig Super-App إنتاجية تغطي التعليم العام والأزهري، القدرات والتحصيلي السعودي، سوق الخدمات والضمان المالي، وطبقة AI عالمية متعددة اللغات.

لا تُعد البيانات المزروعة، أو البطاقات التسويقية، أو حالات `awaiting_payment/unfunded` تنفيذًا إنتاجيًا. كل بند أدناه لا يصبح مكتملًا إلا بعد وجود تدفق مستخدم حقيقي، تخزين دائم، صلاحيات، سجل تدقيق، اختبار قبول، ومصدر محتوى/تكامل معتمد.

## النطاق الكامل المطلوب

1. منظومة K-12 عامة وأزهرية: ابتدائي/إعدادي/ثانوي، خرائط ذهنية، بنوك أسئلة، امتحانات مؤقتة وتصحيح وتحليل ضعف، علوم أزهرية شرعية ولغوية، حفظ المتون والقرآن مع تسميع وتصحيح صوتي.
2. محرك القدرات والتحصيلي: كمي ولفظي وتحصيلي، استراتيجيات حل، CAT معاير، محاكي قياس محوسب وورقي، مؤقت وأقسام، شروحات فيديو، بنك متجدد وتحديث أسبوعي.
3. سوق خدمات: تدريس 1:1، مشاريع وبحوث، خدمات مصغرة، ملفات وتسليم مرحلي، فحص انتحال، تقييمات، Escrow، عمولة 10–20%، تسوية/سحب، نزاعات ولجنة مراجعة.
4. AI/RAG: إدخال نصي وصوتي، فهرسة PDF والفيديو والكتب، Vector DB وembeddings، استرجاع بمصادر وتوقيت، تكيف لغوي وعمري، أسلوب سقراطي ومنع الغش.
5. الترجمة والدبلجة: Whisper/ASR، subtitles للإنجليزية والفرنسية والإندونيسية والأردية والتركية، TTS/voice dubbing وlip-sync، مسارات صوتية وترجمة وتوقيت.
6. البنية التقنية: Web App وPWA/Tablet وتطبيق iOS/Android، REST/GraphQL Gateway، خدمات Auth/LMS/CAT/Marketplace/AI/Live/Translation/Analytics، تخزين فيديو وبيانات ومؤقت وVector DB.
7. حماية المحتوى: HLS/DRM، روابط موقعة، watermark ديناميكي باسم/هاتف الطالب، سياسات تنزيل وتصوير، وتحقق صلاحية الوصول.
8. المدفوعات: مصر (Fawry/Vodafone Cash/InstaPay/Meeza)، السعودية والخليج (Mada/Apple Pay/STC Pay/Tamara/Tabby)، دولي (Visa/Mastercard/Stripe/PayPal)، اشتراكات ودورات وباقات AI ومحافظ وB2B.
9. النمو والقياس: محتوى Short-Form، اختبار تشخيصي مجاني، AI trial محدود، funnel/events/UTM/cohorts، سفراء ومدارس/جامعات، retention/conversion/CAC/LTV.
10. النموذج المالي: 1,000,000–2,500,000 جنيه تأسيسيًا وفق توزيعات الوثيقة، توقعات Q1–Q4، MRR/ARR/GMV/commission/burn/runway/break-even، وتقارير مالية قابلة للتدقيق.
11. التشغيل: MVP ثانوي عام/أزهري + معسكر قدرات، ثم سوق، ثم ترجمة ودبلجة وتطبيق جوال، ثم لغات وشراكات ومدخل Seed؛ مع خطط المخاطر والتحديثات والامتثال.

## ما هو موجود فعليًا الآن

يوجد خادم Node.js وقاعدة MySQL مُدارة وترحيلات متسلسلة، Manus OAuth، أدوار أولية، دورات ودروس وتسجيل وتقدم، بنك CAT تجريبي من 8 أسئلة، جلسات CAT بسيطة، سوق أولي وطلبات غير ممولة، مساعد LLM يحفظ المحادثات، APIs إدارية أولية، وواجهة عربية متجاوبة مع مشغل مسار أولي ونوافذ طلب.

هذه النواة قابلة للتوسع، لكنها لا تثبت جاهزية المحتوى أو الدفع أو الوسائط أو RAG أو الصوت أو التطبيقات المحمولة.

## فجوات تمنع إعلان اكتمال الملف

- المحتوى التعليمي والأزهري والقدرات غير متوفر كأصول إنتاجية مرخصة ومراجعة.
- لا يوجد رفع/بث فيديو أو PDF أو HLS/DRM أو روابط موقعة أو watermark ديناميكي.
- لا توجد Vector DB أو embeddings أو ingestion أو citations/timestamps؛ AI الحالي LLM عام مع label سياقي.
- CAT يحتاج بنكًا كبيرًا ومعايرة وIRT/تقدير قدرة ومؤقتًا وأقسامًا وتحليل ضعف وشروحات فيديو.
- Escrow والدفع والمحافظ والledger والتسويات والعمولات والسحب والاسترداد والنزاعات غير منفذة.
- الترجمة والدبلجة وASR/TTS/lip-sync وتصحيح التلاوة غير منفذة.
- لا توجد PWA أو تطبيقات iOS/Android أو WebRTC أو خدمة تحليلات/BI تشغيلية.
- لا توجد اشتراكات، entitlements، AI tokens، B2B، سفراء، leads، funnel، CAC/LTV، أو تقارير مالية حقيقية.
- يلزم اعتماد قانوني وحقوق نشر وخصوصية القُصّر وحقوق الصوت وفحص الانتحال وسياسات السوق.

## مراحل التنفيذ والاعتماديات

### المرحلة 0 — اعتماد النطاق والحوكمة

اعتماد مسار إطلاق ضيق، الدول والعملات، المحتوى المسموح، سياسة القُصّر والخصوصية، حقوق النشر والصوت، الأسعار والباقات، سياسات الدفع والاسترداد والعمولة والنزاعات، ومؤشرات النجاح. لا يبدأ إطلاق مدفوع قبل هذه المرحلة.

### المرحلة 1 — المحتوى ولوحة الإدارة

إنشاء نموذج منهج/إصدار/وحدة/درس/مورد/سؤال/إجابة/شرح/ترجمة، وواجهة إدارة للمدير والمدرس للمراجعة والنشر والسحب والاستيراد الدفعي. إضافة صلاحيات كاملة وسجل تدقيق. هذه المرحلة شرط للـRAG والاختبارات.

### المرحلة 2 — التخزين والمشغل والحماية

اختيار التخزين والبث وDRM، تنفيذ رفع إداري خاص، تحويل/manifest HLS، روابط موقعة قصيرة العمر، التحقق من entitlement، مشغل، watermark متحرك، ومنع التنزيل المباشر. إضافة PDF viewer آمن وتسجيل موضع الفيديو.

### المرحلة 3 — التعليم وCAT الإنتاجي

إدخال عينة مرخصة من الثانوية العامة ومسار أزهري ومعسكر قدرات. بناء امتحانات K-12 مؤقتة وتحليل ضعف، ثم بنك قدرات واسع، CAT قابل للتهيئة، معايرة baseline/IRT تدريجية، تقارير مهارات وشروحات فيديو.

### المرحلة 4 — RAG رأسي محدود

إضافة transcript segments وPDF chunks وembeddings وVector DB وصلاحيات. ربط سؤال الطالب بـ`lessonId/currentTime/studentProfile`، وإرجاع answer مع citation و`start/end` زمني. إضافة ضوابط تمنع إعطاء واجب جاهز واختبارات جودة الاسترجاع.

### المرحلة 5 — الدفع والسوق في Sandbox

اعتماد Stripe أو مزود أول، بناء Checkout وwebhook idempotent، payment events، ledger، subscriptions/purchases/entitlements، funded/in_progress/delivered/accepted/released/refunded، عمولة 10–20%، payouts، استرداد، ثم تسليم ملفات وفحص انتحال ونزاعات.

### المرحلة 6 — القياس والإطلاق المحدود

تسجيل الأحداث: view، quiz_start/complete، ai_trial، signup، enroll، order، payment، completion، improvement. بناء funnel/cohort/retention وقياس جودة AI وتكلفة الدقيقة/السؤال، ثم إطلاق cohort محدود بمحتوى حقيقي.

### المرحلة 7 — الصوت واللغات والتوسع

إضافة ASR وsubtitles عربية/إنجليزية أولًا، ثم بقية اللغات، TTS/dubbing بموافقات صوتية ومراجعة بشرية، ثم تصحيح التسميع، WebRTC، التطبيقات المحمولة، البوابات الإقليمية، B2B، السفراء والشراكات.

## هيكل المشروع المستهدف

- `client/`: صفحات الطالب والمدرس والإدارة والسوق، المشغل، الاختبارات، المساعد، الترجمة، PWA.
- `server/`: REST/GraphQL gateway، Auth/RBAC، LMS، CAT، Marketplace/Escrow، Payments، AI/RAG، Media jobs، Analytics.
- `db/`: migrations والجداول والـledger والأحداث والنسخ والإصدارات.
- `storage/`: adapters للتخزين الخاص والبث وDRM والأصول الموقعة.
- `ai/`: ingestion، chunking، embeddings، retrieval، prompts، safety، evaluation.
- `media/`: transcription، translation، TTS، dubbing، subtitles، voice sessions.
- `admin/`: إدارة المحتوى والأسئلة والمستخدمين والخدمات والمدفوعات والنزاعات والتقارير.
- `mobile/`: Flutter أو React Native بعد إثبات Web MVP.

## مدخلات لا يمكن توليدها بالافتراض

المناهج والفيديوهات وPDF وبنوك الأسئلة وحقوق استخدامها، قائمة الخبراء والمراجعين، مزود التخزين/DRM، مزود embeddings/vector DB وASR/TTS والترجمة، حسابات الدفع وmerchant/KYC/webhook، الأسعار والباقات والعمولات والضرائب، سياسات القُصّر والخصوصية، بيانات Analytics الأساسية، وقرار Flutter أو React Native.

## سياسة الإنجاز

لا تُستخدم عبارة «تم تطبيق الملف بالكامل» إلا بعد إغلاق كل بند في مصفوفة التغطية، واستبدال كل seed/demo بمصدر حقيقي أو حذف وسمه، واختبار الصلاحيات والدفع والـwebhooks والأصول، وتوثيق نتائج القبول. أي بند يعتمد على مدخلات المالك يبقى `blocked` وليس `done` حتى يتم توفيرها.
